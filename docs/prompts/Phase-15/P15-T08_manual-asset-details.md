# P15-T08: Manual-Asset Details Panel (home + vehicle)

## Context

T06 shipped the Account Details panel for bank accounts. T07 added the
APY sparkline + trend card to it. T08 closes the last gap on the
Accounts page: the single home (Primary Residence) and vehicle (2021
Toyota RAV4) that render as manual-asset rows have no Details panel at
all — clicking them opens `ManualAssetEditModal` to update the value,
but there is no way to *see* the valuation history, source, or linked
loan's scraped fields inline.

T08 adds a read-only `ManualAssetDetailsPanel` under each manual-asset
row, mirroring the T06/T07 visual language:

- **Home:** current estimated value + 12-month valuation sparkline
  (asset-sentiment colored — up is green, down is red), plus the
  linked mortgage's scraped fields (interest rate, payoff today,
  collateral, etc.) via `real_estate.linked_loan_id`.
- **Vehicle:** current value + depreciation sparkline in **neutral**
  color (a depreciating car is expected, not "bad news"), plus the
  linked auto-loan's scraped fields via a new
  `vehicle_assets.linked_loan_id` column (migration v35).

The edit modal stays; T08 is additive.

- `/api/accounts/{id}/details` (reports.py:96) was the only panel
  endpoint — no manual-asset siblings.

**Frontend:**

## Task

### 1. Schema + DAL

- **Migration `v35_vehicle_linked_loan`** — idempotent `ALTER TABLE`
  via `column_exists` helper. Nullable, no backfill. The seeder
  writes the value for the RAV4; real connectors fill it as VIN-aware
  scraping lands.
- **`dal/real_estate.py`** — add `get_valuation_history(conn, name,
  months=None)` (ascending series) and `get_real_estate_details(conn,
  property_id)` (own fields + 12-mo history, linked loan id returned
  but the join itself stays at the router layer).
- **`dal/vehicles.py`** — add `get_valuation_history(conn, vehicle_id,
  months=None)` and `get_vehicle_details(conn, vehicle_id)` (own
  fields + 12-mo history + current `suggested_value` +
  `depreciation_curve` label). Extend `add_vehicle` to accept
  `linked_loan_id`, preserving an existing link on re-run via
  `COALESCE` (parallels the existing `owner_id` treatment).

### 2. Endpoints

- `GET /api/real_estate/{property_id}/details` and
  `GET /api/vehicles/{vehicle_id}/details` in
  `backend/routers/reports.py`.
- A small shared helper `_linked_loan_bundle(conn, account_id)`
  fetches loan_details + apy_latest + 12-mo apy_history for the
  (optional) linked loan. Missing link returns the empty skeleton;
  missing asset returns 404.
- Response shape mirrors `/accounts/{id}/details`: `details`,
  `apy_latest`, `apy_history` are the linked-loan bundle;
  `latest_valuation`, `valuation_history` are the asset's own
  series; vehicle adds `suggested_value` and `depreciation_curve`.

### 3. Seeder

- `dummy_data/vehicle_assets.json` — add `"linked_loan_id":
  "summit_auto"` to the RAV4 row.
- Both seeder entrypoints (`scripts/seed_dummy_data.py::seed_vehicle_assets`
  and `scripts/seed_dummy_db.py::seed_vehicle_assets`) thread
  `linked_loan_id` through. Existing KBB quarterly valuations were
  already seeded — no additional valuation rows needed.

### 4. Frontend — component reuse

- New `frontend/src/lib/valueTrend.ts` — sibling of `apyTrend.ts`.
  Takes `{estimated_value, as_of}` series. Flat threshold is ±$1.
  `valueTrendSentiment(direction, assetKind)` returns
  `"good"|"bad"|"neutral"` — `"real_estate"` follows the asset
  rule (up = good, down = bad); `"vehicle"` returns `"neutral"` on
  any non-flat direction so depreciation doesn't render red.
- New `frontend/src/components/accounts/ManualAssetDetailsPanel.tsx` —
  parameterized component (`assetKind: "real_estate" | "vehicle"`,
  `assetId`, `open`). Reuses `Sparkline`, `formatDetailField`,
  `fieldLabel`, `formatCurrency`, `useOwnerApi`. One component, two
  endpoints, shared hero/grid layout.
- `frontend/src/lib/formatDetailField.ts` — add kind mappings for
  `estimated_value`, `suggested_value`, `purchase_price`,
  `purchase_date`, `year` (new `"year"` kind → bare 4-digit int
  with no thousands separator). Add labels for the same + `make`,
  `model`, `source`, `depreciation_curve`.

### 5. Frontend — AccountsPage wire-up

- Flip `hasDetailsToggle` to allow manual assets: drop the
  `!account._manualKind` gate.
- Render `<ManualAssetDetailsPanel>` for manual rows,
  `<AccountDetailsPanel>` for bank rows; `stopPropagation` on the
  toggle preserves the row-body click → `ManualAssetEditModal` path.
- Closed-accounts list keeps the `!_manualKind` gate untouched —
  manual assets have no "closed" state.
