change): `check_deposit`, `check_written`, `document_upload_commit`,
`merchant_normalization`, `net_worth_recompute`, `portfolio_snapshot`,
`user_goal_crud`. The faults — flow-mapping `{...}` syntax inside an
unquoted scalar, `:` characters splitting list items, `\s` inside a
double-quoted scalar, indented continuations off by 2 spaces, and a
leading backtick on an unquoted value — would all also have broken
any future YAML tooling, so worth catching once. Future authors:
prefer one column per list item; quote anything containing `: `, `{`,
`[`, or backtick at the start of a value.

## Phase 4 — diagrams

**Status:** ✅ done (2026-04-26).

Generated by `build_diagrams.py` (commit it alongside the .mmd files so

after any lineage/*.yaml change:

```

```

Final stats from this generation:

- 82 per-event diagrams + 1 `_overview.mmd` written to `diagrams/`.
- All 83 files pass a basic Mermaid syntax sanity check (every node
  referenced by an edge is also declared; node-shape syntax is balanced).
- Per-event diagram shape: origin (rectangle) → write tables (stadium)
  → direct_consumers + derivations (rectangles) → ui_surfaces (hexagons),
  with external_effects (circles) hanging off the first write table as
  dotted edges. Edges from a consumer/derivation back to its source
  table prefer a `<table>.<col>` match in the YAML's `reads` /
  `inputs`; fallback is the first declared write table.
- Overview shape: four event-class subgraphs → top-5 write tables (by
  combined write+read activity, writers≥1) → top-5 UI surfaces (by
  total fed_by_events count). One arrow per dominant relationship,
  not per individual event.
- External-effect tokens are extracted by priority: leading "SSE
  <topic>" pattern → uppercase identifier (preferring `_`-bearing
  ones like `REFRESH_COMPLETE`) → backticked identifier → first three
  words. No-op effect rows ("No SSE.", "n/a", etc.) are filtered.
  Effects are capped at 6 per diagram to keep them legible; full
  prose stays in the source YAML.

Open follow-ups (none blocking; nice-to-have):

- A handful of effect labels still come out as generic words
  (`Self_commits_at`, `INFO`) when the source prose has no specific
  identifier. The fix is in the source YAML — call out the SSE
  topic / log channel by name where one exists. Acceptable for now;
  the YAML is the source of truth.
- Some events have many derivations × many UI surfaces and produce a
  full crossbar of edges (e.g. `paycheck.mmd`, `investment_buy.mmd`).
  Mermaid renders them fine but they are visually dense. Future
  refinement: use the YAML's `derivations[].fan_out` text to scope
  derivation→UI edges, instead of fanning every derivation to every
  UI. Out of scope this pass — the dense version is still correct
  and grep-able.
